## 和固件的对接关系

固件是 Modbus RTU 从站，`eMBRegHoldingCB()` 收到写保持寄存器就直接 `Parse()`：

| 界面动作 | 写到 40000 起的寄存器 | 读 30000 起 |
|---|---|---|
| 读固件版本 | `1, 0x104` | 2 个：主版本、次版本 |
| 设 VDD (mV) | `1, 0x207, mV` | — |
| 电源开关（需补丁） | `1, 0x208, vdd, vpp, os` | 1 个：1=已执行，0=固件没这条命令 |
| 0x206 快速验证 | `1, 0x206, cmp` | 49 个：`[0]`=err、`[44..46]`=气压、`[47..48]`=温度 |
| SPI 任意事务 | `6, 0, len, b0..bn-1` | len 个：MISO 收回的字节 |

注意两点：

1. 固件回调里比较的是 `usAddress == 40001 / 30001`，但 FreeModbus 在调用回调前会
   `usRegAddress++`（`mbfuncholding.c:123`、`mbfuncinput.c:72`），所以 **PDU 地址要发
   40000(0x9C40) / 30000(0x7530)**，发 40001 会变成 40002 → 越界 → 异常码 0x02。
2. `ParseSPICmd` 要求一次写满 `len + 3` 个寄存器，所以本程序每个事务都是一包写完。

引脚（本板实测）：SCK = PA6(EX_SCL，与 I2C SCL 共用焊盘) / MOSI = PC6 / MISO = PA8 / CS = PB1。

## 使用顺序

1. 选串口 → 连接（固件固定 9600-8-N-1，从站地址默认 1）
2. 读版本，确认通信正常（返回 v1.2 说明 Modbus 通了）
3. **上电** —— 传感器的 VDD 由 `VDD_PU(PA1)` 开关控制，`0x207` 只决定 DAC 电压、
   不接通电源。不上电时芯片 IO 被 ESD 二极管钳到 0V，**SPI 读回来全是 00**
4. **切 4 线 SPI** —— 不发这一句 SDO 不输出；发完要回读 `0x00` 确认等于 `0x01`
5. 读寄存器 / 一键读全部 / 稳定性测试

上面 3→5 步就是 `SPI 收发` 页的 **① 一键初始化（上电 + 切 4 线 + 校验）**，一次点完。

芯片切到 4 线 SPI 后会一直停在 SPI 模式，要回到 I2C 只能断电：
点 **断电复位**（VDD_PU 0 → 300 ms → 1）即可。

### 不改固件也能验证 SPI

点 **② 0x206 快速验证**：固件自己会"设压 → 上电 → I2C 读系数 → 切 4 线 → SPI 读气压温度 → 断电"，
界面直接显示 `err`、气压、温度：

- `err=0x00` 且气压不是 `FFFFFF` → SPI 通了
- `err=0x03` → SPI 读回全 FF，没通
- `err=0x01` → **I2C 段失败**。0x206 前半段是 I2C 读系数，这块板的 I2C 可能没接或芯片不支持，
  跟 SPI 无关；验证 SPI 用 [① 一键初始化] + [触发转换并读] 就够，不必管 0x206。

程序会在跑 0x206 前自动断电复位（避免芯片停在 4 线 SPI 导致 I2C NACK），
跑完再自动恢复上电 + 切 4 线，不会把你留在"一片 00"的状态里。

### 读气压/温度的正确顺序

直接读 0x06 拿到的是上一次转换的残留（甚至没转换过）。点寄存器页的 **触发转换并读**：

```
写 0x30=0x08（触发温度） → 等 60ms → 读 0x09/0x0A
写 0x30=0x09（触发气压） → 等 60ms → 轮询 0x02.bit0 → 读 0x06/0x07/0x08
```

这套时序照抄老 F103 固件（`WF5803/Core/Src/main.c`），已验证可行。

## 固件补丁（建议加，3 行）

固件现在没有单独控制电源的 Modbus 命令，所以工具里的"上电/断电/一键初始化"用不了。
加一条 `0x208` 即可：

`Core/User/Inc/CmdHelper.h`

```c
#define TYPE1_SET_VDD                       0x207
#define TYPE1_SET_POWER                     0x208   /* 新增 */
```

`Core/User/Src/CmdHelper.c` 的 `ParseSystemCmd()` 里加一个 case：

```c
        case TYPE1_SET_POWER:
            /* cmd[2]=传感器VDD  cmd[3]=VPP  cmd[4]=OS，1=开 0=关 */
            SetIoStatus((uint8_t) cmd[4], (uint8_t) cmd[3], (uint8_t) cmd[2]);
            out[0] = 1;          /* 回 1 = 这条命令存在，工具据此判断 */
            break;
```

`SetIoStatus(osOn, vppOn, puOn)` 的声明在 `main.h`，`CmdHelper.c` 已经能用到。
注意别把 `cmd[3]`(VPP) 随手置 1，那是 6.6V 烧录电压。

工具侧会自动识别：回读 `out[0] == 1` 认为支持，`0` 就提示"固件没有 0x208"并建议走 0x206。

## 判读

- 气压 = `rx(0x06)<<16 | rx(0x07)<<8 | rx(0x08)`
- 温度 = `rx(0x09)<<8 | rx(0x0A)`
- 换算（1BAR 公式，照抄 `资料/WF5803_1BAR_IIC驱动包/wfsensor.c`，界面已自动显示）：
  - 气压 `f = raw/8388608`（≥8388608 走负数分支），`kPa = f*125 + 17.5`
  - 温度 `raw>32768 ? (raw-65844)/256.0 : (raw-308)/256.0`，单位 ℃
  - 实测样本：气压 `0x554371` → **100.77 kPa**，温度 `0x1BCF` → **26.6 ℃**，与一个大气压/室温吻合
- 全 `0x00`：**先怀疑没上电**（芯片无电时 IO 被 ESD 钳到 0V）/ MISO 短地 / SDO 对地
- 全 `0xFF`：MISO 悬空（SDO 没接）、没切 4 线、时钟没出去
- 数值乱跳：位序、采样沿或 SCK 太快（加大 `SOFT_SPI_DELAY` 再试）
- 自环校验（PC6↔PA8 短接，传感器断电）通过，说明时钟/采样/MSB 顺序这条链路没问题
